# 文件读写

## 概览

在 Python 中，文件读写是通过内置函数 `open()` 与 **文件对象（File Object）**
来实现的。程序可以通过文件操作将内存中的数据持久化存储到磁盘文件中，或者从磁盘文件中读取数据到内存中进行处理。

### 核心概念：以变量指向文件对象

无论是使用基础的 `open` 赋值写法还是 `with open ... as` 语法，其底层机制都是 **在内存中创建文件对象（File Object /
流对象），并以一个变量指向该文件对象**：

- **普通赋值写法**：在 `file = open(...)` 中，`open()` 函数在内存中创建并返回一个文件对象，等号左侧的变量 `file` 接收并指向该
  **文件对象**。
- **上下文管理器写法**：在 `with open(...) as file:` 中，上下文管理器创建文件对象，关键字 `as` 后的变量 `file` 同样接收并绑定指向该
  **文件对象**。

**后续沿用说明**： 在理解了“以一个变量指向该文件对象”这一底层引用机制后，为了表述直观与简洁，在后续文档内容与日常讨论中，我们通常沿用“变量即文件对象”（即直接将指向该对象的变量称作文件对象）的说法。

**由“文件对象”引出读写操作**： 正因为变量指向的是一个具体的对象，所以对文件的所有操作（包括写入、读取、逐行扫描以及关闭文件），本质上都是
**通过该变量调用文件对象所提供的成员方法或利用其对象特性**：

- 调用对象方法写入：`file.write(...)`、`file.writelines(...)`
- 调用对象方法读取：`file.read(...)`、`file.readline(...)`、`file.readlines(...)`
- 迭代文件对象：`for line in file:`（文件对象原生支持迭代器协议）
- 调用对象方法关闭：`file.close()`

在建立这一认知后，整个文件读写流程就可以清晰地概括为： **获取并以变量指向文件对象 → 调用文件对象的方法进行读写 →
释放与关闭文件对象**。

### 基本语法结构

```python
file_object = open(file="文件路径", mode="打开模式", encoding="字符编码")
```

- **`file`**：目标文件的路径（可以是相对路径或绝对路径）。
- **`mode`**：文件打开模式，决定了是以只读（`r`）、覆盖写入（`w`）还是追加写入（`a`）等方式打开文件。默认为 `'r'`。
- **`encoding`**：文本文件的字符编码格式（如 `'utf-8'`、`'gbk'`）。

## 1. 基础 `open` 与 `close` 写法

### 语法与执行流程

使用 `open()` 函数打开文件后，会返回一个文件对象并赋值给变量。程序通过该 **文件对象**调用其成员方法执行读写操作。操作完成后，必须显式调用该文件对象的
`.close()` 方法关闭文件并释放操作系统资源。

```python
# 打开文件：open() 返回文件对象，由 manual_file 变量指向该对象
manual_file = open("example.txt", mode="w", encoding="utf-8")

# 对文件对象调用 write() 方法写入内容
manual_file.write("Hello, Python!\n")

# 对文件对象调用 close() 方法关闭文件
manual_file.close()
```

### 显式调用 `close()` 的机制与作用

1. **刷新写入缓冲区（Flush Buffer）**：Python 写入文件时通常先将数据暂存到内存缓冲区，调用文件对象的 `.close()`
   会强制将缓冲区内的数据完整写入磁盘。
2. **释放操作系统资源（File Descriptor / Handle）**：操作系统对同时打开的文件句柄数量有上限，未关闭的文件对象会持续占用系统资源。
3. **解除文件锁定**：在部分操作系统（如 Windows）中，处于打开状态的文件对象可能导致该文件无法被其他程序或进程移动、重命名或删除。

### `open-close` 写法的潜在问题

如果在 `open()` 创建文件对象之后、`close()` 调用之前发生了异常报错，或者执行了提前退出分支（如 `return`），程序将跳过
`.close()` 的执行，导致文件对象无法被正常关闭（除非结合 `try-finally` 结构进行防护）。

```python
# 结合 try-finally 确保文件对象的 close 执行
file = open("example.txt", mode="r", encoding="utf-8")
try:
    content = file.read()
finally:
    file.close()
```

## 2. `with open` 上下文管理器写法

### 语法结构

`with` 语句配合 `open()` 使用了 Python 的**上下文管理器（Context Manager）**协议。

```python
with open("example.txt", mode="w", encoding="utf-8") as file:
    # 变量 file 指向 open() 创建的文件对象
    file.write("使用 with open 写入内容\n")
# 离开 with 代码块后，该文件对象被自动关闭
```

在 `with open(...) as file:` 中：

- `open(...)` 创建文件对象并进入上下文管理器环境。
- 关键字 `as file` 将创建出的 **文件对象**绑定给变量 `file`。
- 在缩进代码块内，所有读写均通过该文件对象调用相应方法完成。

### 运行机制与特点

- **自动管理生命周期**：进入 `with` 块时触发上下文管理器的 `__enter__()` 方法获取文件对象；离开 `with` 块时自动触发
  `__exit__()` 方法。
- **异常安全保证**：无论 `with` 代码块是正常执行结束、遇到 `return` 退出，还是中途触发了异常报错，Python 均会保证自动调用文件对象的
  `.close()` 方法关闭文件。
- **无需手动 `close()`**：代码结构清晰，消除了遗漏调用 `close()` 的情况。

## 3. `open-close` 与 `with open` 对比

### 代码结构对比

```python
# 方式一：open 与 close（需手动关闭）
f = open("data.txt", mode="r", encoding="utf-8")
data = f.read()
f.close()

# 方式二：with open（自动关闭）
with open("data.txt", mode="r", encoding="utf-8") as f:
    data = f.read()
```

### 特性对比速查

| 对比维度       | `open` + `close` 写法                                    | `with open` 上下文管理器写法                   |
|:---------------|:---------------------------------------------------------|:-----------------------------------------------|
| **关闭机制**   | 需显式调用 `file.close()`                                | 离开代码块时由解释器自动调用 `close()`         |
| **异常安全性** | 若中间代码报错，可能跳过 `close()`，需搭配 `try-finally` | 遇到异常、`break` 或 `return` 均会确保自动关闭 |
| **代码冗余度** | 需要多行代码维护打开与关闭状态                           | 结构紧凑，缩进范围即为文件生命周期             |
| **适用场景**   | 跨函数/长生命周期的特殊文件对象传递                      | 常规文件读写操作的标准结构                     |

## 4. 字符编码（`encoding`）与 `utf-8`

### 什么是字符编码

计算机底层只能存储和处理二进制数据（`0` 和 `1`，即字节 Bytes）。

- **编码（Encoding）**：将人类可读的字符（如文字、字母、符号）转换为二进制字节序列的规则。
- **解码（Decoding）**：将二进制字节序列还原为字符文本的规则。

### 为什么需要显式指定 `encoding`

如果在调用 `open()` 时未传入 `encoding` 参数，Python 会使用 **操作系统当前的默认区域编码**（Locale Encoding）：

- **Windows（简体中文环境）**：通常默认为 `gbk`（或 `cp936`）。
- **Linux / macOS**：通常默认为 `utf-8`。

当一个以 `utf-8` 编码保存的文件在 Windows 系统上以未指定编码的方式打开时，Python 会默认以 `gbk` 规则解码，导致出现乱码或直接抛出
`UnicodeDecodeError` 异常：

```python
# 未指定 encoding 可能在不同操作系统上表现不一致
with open("data.txt", mode="r") as f:
    text = f.read()  # 若文件编码与系统默认编码不一致，将报错 UnicodeDecodeError

# 显式指定 encoding 保证跨平台一致性
with open("data.txt", mode="r", encoding="utf-8") as f:
    text = f.read()
```

### 什么是 `utf-8`

`utf-8`（8-bit Unicode Transformation Format）是一种通用的变长字符编码标准：

1. **字符集覆盖广**：支持 Unicode 标准中收录的全球几乎所有语言文字（中文、英文、日文、阿拉伯文、拉丁文等）以及 Emoji 表情符号。
2. **变长编码节省空间**：ASCII 字符（如英文字母和数字）占用 1 个字节，常用汉字通常占用 3 个字节。
3. **跨平台与标准化**：现代互联网协议、Web 页面、跨平台应用程序和主流开发工具普遍采用 `utf-8` 作为标准文本编码。

在处理文本文件读写时，显式指定 `encoding="utf-8"` 可以确保文件在不同操作系统和运行环境之间具备统一的编解码结果。

## 5. 文件打开模式（`mode`）

打开模式决定了程序对文件拥有的操作权限（读、写、追加）以及文件指针（读写位置）的初始状态。

### 核心三种模式：`'r'`、`'w'`、`'a'`

#### 1. `'r'`（Read：只读模式）

- **行为**：以只读方式打开文件，文件的指针位于开头。
- **文件不存在时的表现**：抛出 `FileNotFoundError` 异常。
- **常用读取方法**：
    - `file.read()`：一次性读取文件全部内容并返回字符串；可传参 `file.read(size)` 指定读取的字符数。
    - `file.readline()`：读取单行内容（包含末尾的换行符 `\n`）。
    - `file.readlines()`：读取所有行并作为字符串列表返回。
    - `for line in file:`：直接逐行迭代文件对象（内存占用低，适合处理大文件）。

```python
with open("note.txt", mode="r", encoding="utf-8") as file:
    content = file.read()
    print(content)
```

#### 2. `'w'`（Write：覆盖写入模式）

- **行为**：以只写方式打开文件。
- **文件已存在时的表现**： **直接清空（截断）原有文件内容**，从文件开头重新写入。
- **文件不存在时的表现**：自动在指定路径创建新的空文件。
- **常用写入方法**：
    - `file.write(str)`：将字符串写入文件。
    - `file.writelines(list_of_strings)`：将字符串序列依次写入文件（不会自动添加换行符）。

```python
with open("note.txt", mode="w", encoding="utf-8") as file:
    file.write("第一行新内容\n")
    file.write("第二行新内容\n")
```

#### 3. `'a'`（Append：追加写入模式）

- **行为**：以追加方式打开文件，文件指针自动移动到文件末尾。
- **文件已存在时的表现**：保留原有全部内容，新写入的数据直接接在文件末尾之后。
- **文件不存在时的表现**：自动创建新的空文件并开始写入。

```python
with open("note.txt", mode="a", encoding="utf-8") as file:
    file.write("追加在末尾的内容\n")
```

## 6. 文件打开模式速查表

| 模式字符   | 模式名称     | 读写权限   | 指针初始位置 | 文件不存在时的行为              | 文件已存在时的行为                             |
|:-----------|:-------------|:-----------|:-------------|:--------------------------------|:-----------------------------------------------|
| **`'r'`**  | 只读（默认） | 仅读取     | 文件开头     | 抛出 `FileNotFoundError`        | 正常打开，指针在开头                           |
| **`'w'`**  | 覆盖写入     | 仅写入     | 文件开头     | 创建新文件                      | **清空已有内容**并从头写入                     |
| **`'a'`**  | 追加写入     | 仅写入     | 文件末尾     | 创建新文件                      | 保留已有内容，新数据接在末尾                   |
| **`'r+'`** | 读写模式     | 可读可写   | 文件开头     | 抛出 `FileNotFoundError`        | 保留内容，覆盖写入开头位置                     |
| **`'w+'`** | 读写模式     | 可读可写   | 文件开头     | 创建新文件                      | **清空已有内容**并重新写入                     |
| **`'a+'`** | 读写追加模式 | 可读可写   | 文件末尾     | 创建新文件                      | 保留内容，写入数据始终追加在末尾               |
| **`'b'`**  | 二进制模式   | 视搭配而定 | 视搭配而定   | 视搭配而定（如 `'rb'`, `'wb'`） | 以字节（`bytes`）为单位读写，不使用 `encoding` |
